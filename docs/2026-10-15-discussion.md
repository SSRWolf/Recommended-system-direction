## 2. 老师反馈与概念澄清

### 2.1 交流内容摘要

学生表达了对对话推荐的兴趣，认为对话可能提供当前需求和动态偏好，并询问引入 LLM 后是否能获得可解释的结果。

老师对该方向当前的前景持保留态度，重点指出：

- 预测或决策任务是否都需要自然语言作为中介，值得重新审视。
- 以文本理解和推理作为中介完成后续预测，可能不够高效。
- 输出自然语言理由，与特征层面的可解释性不同。
- 建议阅读群里转发的文章，深入了解其合理性及局限。

之后提出了“对话数据用于直接决策模型”和“从 RAG 缓解幻觉切入”的想法。老师建议先调研，并约定 2026-10-16 15:30 在实验室面谈。这不等于已确定选题。

### 2.2 对话输入、决策过程、结果表达可以分开

| 层面 | 问题 | 可采用的形式 |
|---|---|---|
| 输入 | 怎样获得用户需求和约束？ | 对话文本、历史行为、画像 |
| 决策 | 怎样选择或排序物品？ | 向量表示、结构化特征、直接评分，或生成式预测 |
| 输出 | 怎样展示推荐和依据？ | 物品列表、模板、自然语言回复 |

点击与购买历史本身也可以是动态序列。对话的额外价值主要在于显式意图、否定反馈和当前约束，不能简单表述为“行为数据静态、对话数据动态”。

一种可研究的流程是：对话 → 偏好表示/约束 → 候选召回与排序 → 推荐结果。是否增加文字推理，应由任务与实验决定。

### 2.3 三种不同的正确性

- **事实正确性**：商品真的有被描述的属性吗？
- **偏好依据**：用户真的表达过该需求吗？
- **解释忠实性**：声称的理由实际影响了推荐决策吗？

一个理由即使事实正确、语言流畅，也可能是事后编造的理由，未必反映模型决策依据。特征归因同样需要验证，不自动保证正确。

参考：[FIRE: Faithful Interpretable Recommendation Explanations，2025 预印本](https://arxiv.org/abs/2508.05225)。

## 3. 老师转发的文章：Kev 直接决策模型

- 微信文章：《1天拿下6.3k星！基于Qwen的开源决策模型系列，最小0.8B，自带模型微调skill》。
- [微信原文](https://mp.weixin.qq.com/s/Zd6Wsy0NvSYPpRGjArqOZw)
- [Kev 官方项目](https://github.com/jaredpalmer/kev)

文章介绍基于 Qwen 的 Kev 模型，提供给定选项的选择、判断和评分等能力。文章中的模型型号、热度和项目当前版本可能不同，实验需固定具体版本。

| 方式 | 简化流程 |
|---|---|
| 生成式推荐 | 读取需求和候选 → 逐 token 生成分析或答案 → 提取结果 |
| 直接决策 | 读取需求和候选 → 计算选项分数或概率 → 返回结果 |

关键澄清：Kev 仍然读取并处理文本，也依赖语言模型基础能力。省去输出文本的生成过程，不等于完全摆脱文本理解；不输出文字推理，也不等于没有内部计算或推断。

### 对推荐研究的启发与边界

可以设想“对话 → 检索候选与资料 → 直接评分 → 推荐”的系统，需要时单独生成解释。但：

- 项目演示与热度不能证明推荐效果。
- 直接评分、分类和排序已有长期研究积累，换一个模型运行数据集不自动构成创新。
- 固定物品目录和 ID 输出可以避免自由编造物品名称，但模型仍可能选错、违反约束或误解需求。
- 有限候选选择与大规模商品库推荐不同，仍要考虑候选召回、规模和偏差。

候选研究问题：**相同对话、候选集合及可比计算条件下，直接评分与生成式推荐在准确率、约束满足率和延迟上有什么差异？**

建议比较传统排序模型、直接评分模型、不生成文字推理的 LLM，以及生成文字推理的 LLM。避免将模型大小、训练数据与候选质量差异混为推理方式的效果。

## 4. RAG 从“消除幻觉”收窄为可验证问题

RAG 主要解决外部知识如何进入并支撑输出。它不会自动回答“推荐决策是否需要文本中介”，两者可以分别研究。

检索后只输出物品分数或 ID，更准确地称为检索增强的推荐决策；包含生成环节时，再分析 RAG 对生成可靠性的影响。

| 错误类型 | 例子 | 可能切口 | 评价思路 |
|---|---|---|---|
| 物品不存在 | 编造电影或商品型号 | 真实目录、ID 对齐、受约束输出 | 无效物品率 |
| 属性错误 | 声称商品支持它没有的功能 | 属性证据检索、核验、生成约束 | 属性错误率、证据支持率 |
| 偏好编造 | 用户没说喜欢某品牌，却据此推荐 | 对话证据定位与偏好抽取 | 无依据偏好比例 |
| 证据过时或冲突 | 使用旧价格、混淆型号 | 时间与版本过滤、冲突处理 | 过时信息使用率、冲突处理结果 |
| 违反需求 | 推荐超预算物品 | 结构化条件、过滤与校验 | 约束满足率；不一定属于幻觉 |

这些指标名称是实验设计建议，需明确分母、标注规则与评估范围。没有证据支持，不自动等于现实中为假；与参考答案不同，也不自动意味着幻觉。

第一轮调研应确定：**一种错误 + 一种证据来源 + 一套评测方法**。例如“利用商品属性证据减少推荐理由中的属性编造”比“用 RAG 消除推荐幻觉”更容易检验，但仍需查新。

### 7.3 格式与最小读取代码

文件虽是 .txt，但每行都是一条完整 JSON 记录，按 JSONL 读取。一条记录是一整段对话，不是一句话。

```python
import json
from pathlib import Path

path = Path(r"E:\postgraduate\datasets\DuRecDial2\data\zh_train.txt")
with path.open(encoding="utf-8") as f:
    sample = json.loads(f.readline())

print(sample.keys())
for index, text in enumerate(sample["conversation"], start=1):
    print(f"第{index}轮：{text}")
```

| 字段 | 含义 | 注意 |
|---|---|---|
| conversation | 整段对话 | 预测某轮只能看到此前历史 |
| user_profile | 用户背景与偏好 | 是否可见由任务协议决定 |
| situation | 对话情境 | 不能默认线上都有此信息 |
| goal | 整段目标规划 | 可能提前暴露未来推荐目标 |
| goal_type_list | 每轮目标类型 | 标签不应无条件作为输入 |
| goal_topic_list | 每轮话题/实体 | 提及不等于推荐成功或用户接受 |
| knowledge | 每轮对应的知识三元组列表 | 参考证据不等于真实检索结果；评论不等于客观事实 |

原始记录没有显式逐轮角色字段，不能默认所有对话都由用户先发言。原文的分词空格和目标阶段标记也要按明确协议处理。

### 7.4 从一段对话构造一个样本

实际读取的第一条训练对话中，第 9 轮用户改变了电影偏好，第 10 轮给出新的电影推荐。

- 模型输入：第 1–9 轮。
- 预测目标：第 10 轮回复，或根据任务定义提取的推荐物品。
- 参考信息：第 10 轮答案、主题及对应知识。
- 不可见：目标答案和未来对话。

该教学样本在本地 preview/next_turn_example.json 中，model_input 与 reference_only 分开。它不是完整的官方预处理协议。

## 8. 开始 RAG 实验前需要明确的边界

1. **不要泄漏答案**：完整目标、未来对话、目标轮对应知识可能提前透露答案。
2. **区分检索和给定知识**：直接使用正确参考知识属于 oracle/受控知识设置，不能当作端到端检索效果。
3. **明确知识库来源**：可先用训练集知识或预先确定的独立知识库；不可把测试答案和答案对齐证据悄悄加入检索库。
4. **缺少幻觉标签**：DuRecDial 2.0 不能直接当作完备的幻觉检测基准，需定义并标注错误。
5. **保持可比性**：固定生成模型，分别检查检索是否找到依据、回答是否遵循依据，以及推荐效果和成本。
