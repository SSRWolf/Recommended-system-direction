# 序列挖掘与 RAG：从高频错误模式到学习建议

## 核心思路

这个方案想回答一个问题：**学生在不同题目上反复出错，背后是否存在共同的学习困难？我们能否根据这些线索，推荐更有针对性的练习？**

做法可以概括为：**先找出反复出现的行为，再查找相关教学资料，最后让大模型结合证据提出解释和建议。**

| 环节 | 负责做什么 | 通俗理解 |
| --- | --- | --- |
| 序列挖掘 | 从学习记录中找出反复出现的行为片段 | 找规律 |
| RAG（检索增强生成）中的检索 | 根据当前学生的行为，查找相关模式、题目解析和知识说明 | 找依据 |
| 大模型（LLM） | 综合行为和教学资料，分析可能的困难并提出建议 | 解释与建议 |
| 推荐与检查 | 选择真实可用、符合先修要求和难度的资源 | 安排下一步学习 |

### 先弄清楚：数据里能看到哪些行为

结合已整理的[数据字段与样例分析](datasets.md)，研究可以从“答对还是答错”扩展到“答错之后做了什么”。不同数据集记录的内容不同，可以先分成六类：

| 行为类别 | 能观察什么 | 可以研究的问题 |
| --- | --- | --- |
| 答题 | 正确、错误、部分得分 | 哪些题目或知识点反复出现困难？ |
| 尝试 | 重试、修改选项、多次提交 | 学生是否持续尝试，后来是否成功？ |
| 求助 | 使用提示、查看答案、访问解析 | 学生在什么情况下寻求帮助？之后能否独立作答？ |
| 时间 | 首次响应耗时、总耗时、行为间隔 | 困难是当前出现，还是在较长时间内持续存在？ |
| 资源使用 | 访问页面、进入讲解、播放或暂停媒体 | 学生怎样使用外部材料，之后的表现是否变化？ |
| 知识点切换 | 连续练习、切换知识点、返回之前的知识点 | 学习路径是否有重复规律，与知识关系有什么联系？ |

“知识点切换”是可观察的行为；学生能否把已学知识用于新情境，才是需要另外检验的知识迁移。

**要先区分两种数据：完整操作记录和汇总计数。** 前者可能告诉我们“先答错、再看提示、最后答对”；后者可能只告诉我们“这道题用了3次提示”。只有计数时，可以分析提示使用多少，但不能补出提示与答题的先后顺序。

### 第一步：看看学生经常在哪里、怎样出错

例如，下面是四名学生的学习记录。这里只用于说明方法，不是真实实验数据；“比例错”表示比例题答错，其余同理。

| 学生 | 按时间排列的行为 |
| --- | --- |
| A | 比例错 → 工程错 → 行程错 |
| B | 比例错 → 工程错 → 方程对 |
| C | 比例对 → 工程错 → 行程错 |
| D | 比例错 → 工程错 → 行程错 |

算法可以找到：

- “比例错 → 工程错”：在 A、B、D 中出现，共 3 人，占 75%。
- “工程错 → 行程错”：在 A、C、D 中出现，共 3 人，占 75%。
- “比例错 → 工程错 → 行程错”：在 A、D 中出现，共 2 人，占 50%。

这里的比例叫作**支持度**，就是“多少学生出现过这个模式”。按学生计算时，同一个学生重复出现十次，也只计一名学生。

第一版可以用 PrefixSpan 挖掘这类模式，并明确哪些行为允许跳过、间隔可以多长。除了题目和正误，还可以记录作答用时、重试和提示使用，寻找“答错 → 请求提示 → 答对”等过程。具体错误类型，例如“方程建立错误”，需要实际答案、解题步骤或可靠标注支持。

### 从错误扩展到五种值得关注的模式

下面是可以尝试挖掘的模式。它们描述学习过程，后续再检验是否反映某类需求。

| 模式 | 先统计什么 | 再检验什么 |
| --- | --- | --- |
| 答错 → 重试 → 答对 | 连续错误次数、到首次正确需要的尝试次数、错误后多久重试 | 后续同类题能否独立完成？ |
| 答错 → 提示 → 答对 | 使用提示的作答比例、提示次数、求助后的表现 | 逐步减少提示后是否仍能完成？ |
| 较长时间作答 → 答错 | 错误题耗时、同类题的耗时差异 | 控制题目难度和个人作答习惯后，是否仍与后续困难有关？ |
| 知识点 A → B → A | 知识点切换、返回频率、常见转移组合 | 返回是否与之前错误相关，还是由课程安排造成？ |
| 作答 → 访问解析或讲解 → 再次作答 | 访问发生在何时、使用了哪些资源、之后的作答表现 | 使用资源后能否在新题上独立完成？ |

例如，三名学生最终都答对了，但过程分别是“独立答对”“看提示后答对”“查看答案后答对”。可以保留这些差异，并用后续无帮助作答检验独立掌握程度。

最初可以先计算几个容易解释的指标：

- **提示使用率：** 使用过提示的作答记录数 ÷ 提示信息已知的作答记录总数。它衡量使用频率，“提示依赖”还需后续验证。
- **错误题平均耗时：** 统计有有效耗时的错误记录，并同时报告记录数；与正确题比较时匹配题型和难度。无有效记录时标为缺失。
- **知识点转移比例：** 从知识点 A 转向 B 的次数 ÷ 从 A 出发的全部有效转移次数。多知识点题目先明确计数规则。
- **资源访问后的表现：** 分别观察同题再次作答和新题表现，避免把记住答案当作知识掌握。

用时长可能包含停顿或离开页面，因此文档中优先称“作答耗时”，不直接称为纯粹的思考时间。媒体播放、暂停和游标可作为使用线索，是否看完需结合完整起止日志和资源时长判断，理解程度仍需测评。

### 第二步：把值得关注的模式整理成证据

发现模式后，保存它涉及的知识点、出现人数、统计范围，以及能回到原始日志的记录编号。再检查：换一批学生或换一个时间段，这个模式是否仍然存在？它是否比单看正确率提供更多信息？

这些经过筛选的记录组成“行为模式库”。分析当前学生时，先检查他的历史中出现了哪些模式，再取出对应证据。

**高频表示一种行为经常出现；它反映什么困难，还要结合题目与教学知识判断。** 例如，多人按“比例题 → 工程题”顺序出错，也可能与课程安排或题目难度有关。

### 第三步：根据行为线索，检索相关知识和教学资料

如果当前学生也出现了“比例错 → 工程错 → 行程错”，可以围绕这些具体题目查找：

- 各题考查什么知识，是否依赖共同的先修知识；
- 正确解法是什么，常见错误发生在哪一步；
- 学生实际答案或步骤是否与某类错误相符；
- 有哪些基础练习、讲解材料或验证题可以使用。

例如，先按知识点编号和行为顺序查找匹配模式，再根据题干、解析的内容查找相关教学材料。RAG就是让大模型在生成回答前，先获得这些与当前问题相关的外部资料。

这样，大模型得到的是两类依据：**学生实际做过什么，以及相关知识应该怎样理解和练习。**

### 第四步：让大模型提出有依据、可以验证的解释

假设题目解析表明，这几道题都需要先找出数量关系，再建立方程。大模型可以据此提出：

> 你最近在比例、工程和行程题上都出现了错误。这几道题都涉及数量关系和方程建立，值得进一步检查你在这一步是否遇到了困难。
>
> 目前只有答题结果，还不能确定错误都发生在列方程这一步。可以先选一道新的应用题，只要求写出数量关系和方程，再根据这一步的表现安排练习。

如果已有解题步骤明确显示多次列式错误，就可以加入这部分证据。只有正误记录时，输出应保留为待验证解释。

每条判断都应说明依据来自哪些行为和材料。大模型负责汇总、解释和提出验证办法，统计次数和模式匹配由程序完成。

### 第五步：根据验证结果安排学习内容

| 验证发现 | 下一步可以安排什么 |
| --- | --- |
| 比例基础概念不清楚 | 比例关系讲解与基础练习 |
| 理解概念，但不会从题目中找数量关系 | 不同情境下的数量关系提取与列式练习 |
| 看提示能完成，独立作答仍困难 | 逐步减少提示的同类练习 |
| 同类题能独立完成 | 换一个情境，检查知识能否迁移 |

推荐时使用资源库中真实存在的材料，并检查先修要求、难度和学习时间。之后再观察学生的表现，更新证据和建议。

### 先选一个数据集，做一个小实验

可以根据要回答的问题选择起点：

| 想先研究什么 | 可以优先检查的数据 |
| --- | --- |
| 答错后是否重试、怎样求助、随后发生什么 | OLI操作日志 |
| 作答与解析、讲解访问怎样连接 | EdNet-KT3；需要媒体操作时再考虑KT4 |
| 尝试次数、提示次数和耗时是否提供额外信息 | ASSIST2009/2012或Algebra |
| 知识点切换与先修关系 | Junyi及其题目表 |
| 每天或每周的课程资源参与 | OULAD |
| 主观难度、置信度与实际表现的差异 | 取得并核验DBE-KT22记录后再做 |

初始实验可从OLI或EdNet-KT3选一个开始，而不是同时合并所有数据集。按以下步骤推进：

1. **列一张行为编码表。** 写清原字段、动作含义、时间、知识点和对应的原始记录。只编码数据实际记录的行为。
2. **构造学生序列。** 区分题内操作和跨题练习，按学生、时间与会话整理。以下只是编码示意，KC代表知识点：

   ```text
   (KC1, 答错) → (KC1, 请求提示) → (KC1, 答对)
   → (KC2, 答错) → (KC2, 再次答错)
   ```

   对于EdNet，将“访问解析”按原动作单独编码，不替换成“请求提示”。
3. **挖掘重复模式。** 先用简单连续片段作为对照，再用PrefixSpan；需要比较算法时再考虑SPADE或GSP。
4. **检查模式是否有用。** 统计出现的学生比例、知识点和时间分布，并在独立学生数据上检查与后续表现的关系。模式频繁出现并不保证能区分困难。
5. **把有效模式接入RAG。** 匹配当前学生，检索相关知识与资源，让大模型提出有出处的解释和可验证的建议。

另设一组对照：只用答题正误、加入其他行为、再加入知识关系。这样可以逐步检验行为信息和知识图谱各自带来了什么帮助，而不是把所有改进都归于大模型。

### 这个方案需要验证什么

研究重点是：**挖掘出的行为模式，能否帮助我们更准确地发现学习困难，让建议更有针对性、也更容易核查依据？**

可以比较“原始日志直接输入大模型”“行为模式输入大模型”“加入检索资料后的方案”，并在相同条件下检查分析是否符合事实、建议是否合理。是否真正提高学习效果，还需要后续测评。

本思路连接[六个研究方向](directions.md)中的多行为分析、知识关系、行为模式和学习推荐。下面各节展开具体实现与实验设计；目前尚未开展模型实验。

## 1. 整体流程

```text
学生行为日志
    ↓ 统一事件定义，保留时间、题目、知识点和来源
序列挖掘：发现错误、重试、求助与恢复的重复模式
    ↓ 按支持度、区分度、稳定性筛选
行为模式库
    ↓ 匹配当前学生截至当前时点的历史
当前学生的行为证据
    ↓ 检索知识点说明、先修关系、教学策略与可用资源
LLM：观察事实 → 可能解释 → 学习建议
    ↓ 核验引用、资源ID、先修要求与时间预算
可追溯的个性化建议或学习路径
```

直接把行为特征放入提示词属于结构化证据输入；根据当前学生从模式库或教学知识库检索相关内容，再用于生成，构成此处的 RAG 流程。初始原型可以使用知识点与行为类型的规则检索，文本丰富后再比较关键词和向量检索。[RAG 方法来源](https://arxiv.org/abs/2005.11401)

## 2. 挖掘对象：错误前后发生了什么

| 模式示例 | 可直接观察的事实 | 需要检验的解释 |
| --- | --- | --- |
| 答错 → 重试 → 答错 | 重复尝试后仍失败 | 是否存在知识缺口，或题目本身较难 |
| 答错 → 提示 → 答对 | 求助后完成作答 | 后续能否独立完成同类题 |
| 答错 → 解析 → 新题答对 | 查看解析后出现成功 | 是否能够迁移到不同形式的题 |
| 知识点 A 错 → B 错 → C 错 | 跨知识点出现错误 | 是否涉及共同先修知识 |

分别处理两种粒度：题内操作序列用于分析学生怎样应对困难；跨题序列用于分析困难是否持续、迁移或恢复。保留错误后的成功和恢复行为，才能比较不同应对过程。

## 3. 初始算法与模式筛选

第一版以连续 n-gram 为基线，再加入 PrefixSpan。连续 n-gram 捕获相邻事件片段；PrefixSpan寻找保持先后顺序、允许中间存在其他事件的频繁子序列。使用后者时明确最大间隔、模式长度以及是否跨题、跨会话；所选实现未提供间隔约束时，需要在匹配阶段验证。[PrefixSpan 方法来源](https://scholars.duke.edu/publication/1530847)

例如，“答错 → 查看题目 → 请求提示 → 答对”可以匹配允许间隔的“答错 → 提示 → 答对”；保存证据时仍保留完整原片段，让读者看到被跳过的操作。

高频模式还需经过以下筛选：

| 维度 | 检查内容 |
| --- | --- |
| 支持度 | 出现该模式的学生或会话比例；预先固定统计单位，另记单个学生的重复次数 |
| 区分度 | 后续持续困难与恢复良好的两组历史中，模式出现率是否有差异 |
| 稳定性 | 换学生、题目、时间窗口后是否仍能观察到 |
| 增量信息 | 控制历史正确率、活动量和题目难度后，是否仍有助于预测后续表现 |

模式库只用训练集发现；后续表现可作为训练阶段筛选目标，应用时只匹配当前时点以前的历史。独立测试集用于检验稳定性和有效性。已有方法研究比较了简单行为特征聚类与序列聚类，强调通过跨任务一致性和外部关联验证模式意义。[行为模式泛化研究](https://link.springer.com/article/10.1186/s40536-026-00289-8)

## 4. 证据记录应保存什么

每条模式保存规则、适用粒度、统计口径和训练集支持度。匹配到当前学生后，补充其具体证据：

```text
pattern_id：模式标识
pattern：事件序列及允许的间隔
scope：题内 / 跨题 / 会话
knowledge_ids：涉及知识点
matched_spans：实际匹配的完整日志片段
source_record_ids：原始记录编号
time_range：片段起止时间
student_match_count：当前学生的匹配次数
support_unit / support_count / total_units：训练集统计口径与计数
available_at：证据何时可用于预测
```

这是结构模板，没有填入虚构统计值。对“提示依赖”“推理困难”等解释另存假设及验证依据，避免把推断混入原始行为事实。

## 5. 检索什么教学知识

行为证据说明学生做了什么；教学知识帮助解释相关知识内容并选择学习资源。检索输入可由“知识点＋行为模式＋学习目标”构成，检索结果包括：

- 知识点定义、先修关系和典型错误说明；
- 经教师整理的辅导策略；
- 题干、选项、提示正文和解题解析；
- 课程描述、讲义或视频字幕，以及可访问的资源ID。

“资源文本”指上述内容文字。题目ID、提示次数和学生提交的答案，分别是索引、统计量与作答内容，不能替代题干或提示正文。只有知识点名称时，可先生成知识点级建议；具体错误步骤的分析需要更细的题目与作答证据。

检索记录保留来源、适用知识点和版本。大模型输出按“观察事实—候选解释—建议与验证方式”组织，并引用行为记录和教学材料。路径中的资源ID与先修关系由程序检查。

## 6. 当前数据的适配

基于[现有工作簿分析](datasets.md)，OLI操作日志、Junyi操作日志、EdNet-KT2/3/4适合优先检查事件顺序。ASSIST2012的actions字段需要解析和核验。

Algebra的Incorrects/Hints等是汇总计数，无法仅凭这些字段还原“先错→提示→答对”的具体顺序。EdNet的respond表示选择答案，反复respond可能是修改选项；需结合提交事件和题库答案才能定义评分结果。

当前Excel提供少量样例与字段说明。实际挖掘须取得完整日志，核对学生标识、时间、事件类型、跨表关联及资源文本。

## 7. 最小验证实验

| 组别 | 输入与处理 | 比较目的 |
| --- | --- | --- |
| A | 原始历史日志直接输入LLM | 建立无模式提取的对照 |
| B | 挖掘后的行为证据输入LLM | 检验结构化模式提取的作用 |
| C | 原始历史日志＋检索教学知识 | 单独检验知识检索的作用 |
| D | 行为模式证据＋检索教学知识 | 检验完整方案及两部分的配合 |

使用相同LLM、测试学生、学习目标和可用资源库；统一上下文预算与截断规则，并报告输入长度和检索成本。先比较：

1. 事实一致性：陈述是否与学生日志相符。
2. 证据可追溯性：引用是否支持相应解释或建议。
3. 建议质量：教师盲评的针对性、可执行性和知识适配。
4. 路径约束：资源存在率、先修违规率和时间预算满足率。

学习效果另以独立测评或干预实验检验。可形成的研究问题是：**经验证的错误相关子序列证据，能否提高大模型分析学习困难与生成教学建议的准确性和可追溯性？**
